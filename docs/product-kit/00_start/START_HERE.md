# 开发启动说明

## 1. 交付目标

最终应交付一个可部署、可测试、可扩展的完整产品，包含：

- 微信小程序；
- Android/iOS APP；
- Web 管理后台；
- 统一后端 API；
- 数据库迁移与种子数据；
- 天气、通知、分享、导入导出基础能力；
- 自动化测试与部署说明。

## 2. 第一版必须支持的场景

### 个人用户

- 注册、登录、退出、注销；
- 创建常用班次，例如早班、晚班、夜班、休息；
- 按天设置排班或按循环规则生成排班；
- 月视图、周视图、今日详情；
- 显示上班时间、下班时间、时长、地点、备注；
- 根据班次地点与日期显示天气；
- 临时修改某一天班次，且不影响其他日期；
- 设置上班前提醒和天气提醒；
- 生成图片或链接分享班表；
- 查看改班记录和本月班次统计。

### 组织用户与管理员

- 创建组织、部门和员工；
- 创建班次模板；
- 日历式、表格式批量排班；
- 导入、导出排班；
- 员工提交改班申请；
- 管理员审批或驳回；
- 排班冲突、人员缺口、异常天气提示；
- 仪表盘与基础统计；
- 角色权限、审计日志、分享模板管理。

## 3. 推荐实现顺序

1. 建立 monorepo、数据库、身份认证、共享类型与设计令牌。
2. 完成班次、排班实例、循环规则和临时改班领域模型。
3. 完成用户端月历、今日班次、编辑与分享基础流程。
4. 完成管理后台排班、员工、审批与统计。
5. 接入天气、通知、海报、导入导出。
6. 补齐安全、日志、测试、性能与部署。

## 4. 不可妥协的原则

- 跨午夜班次必须正确计算时长和归属日期。
- 临时改班默认只修改指定排班实例，不能暗中改动循环规则。
- 所有管理员写操作必须记录审计日志。
- 分享默认隐藏敏感信息，不包含手机号、精确地址或内部备注。
- 天气不可阻塞排班核心流程；天气服务失败时页面仍可正常使用。
- 计划任务必须幂等，避免重复提醒和重复生成排班。
- 用户数据按组织隔离，任何接口都不能只依赖前端传入的组织 ID。
- 小程序、APP、后台使用同一套领域枚举和 API 数据结构。
