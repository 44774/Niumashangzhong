# Codex 总提示词

你正在开发一个名为“工作日历”的完整产品。仓库内 `docs/product-kit/` 包含产品、UI、架构、数据、API、测试和运营规范。你必须先完整读取这些资料，再开始编码。

## 总目标

交付微信小程序、Android/iOS APP、Web 管理后台和统一后端服务。用户可以查看和管理每天的班次、上下班时间、天气、提醒、临时改班与分享；组织管理员可以管理员工、模板、批量排班、改班审批、统计与权限。

## 默认技术方向

- monorepo；
- TypeScript 全栈；
- 小程序与 APP 使用 uni-app + Vue 3；
- 后台使用 Vue 3 + Vite；
- 后端使用模块化 Node.js 服务；
- PostgreSQL + Redis；
- OpenAPI 生成类型安全客户端；
- 所有设计颜色、间距、圆角、阴影来自设计令牌。

若仓库已有技术栈，优先遵守仓库现状，但必须说明与本规范的差异并保持功能等价。

## 工作方式

1. 先列出你读取的关键文档和理解到的约束。
2. 检查仓库结构、现有代码、测试和配置。
3. 给出本阶段要修改的文件清单和验收点。
4. 实现真实可运行的代码，不使用静态截图冒充 UI，不留下无说明的占位功能。
5. 对外部服务建立接口层和本地 mock，确保无密钥时仍可开发和测试。
6. 为复杂业务编写单元测试，为关键用户流程编写集成或端到端测试。
7. 运行 lint、类型检查、测试和构建，修复所有由本次变更造成的问题。
8. 输出完成项、验证结果、已知限制和下一步。

## 领域约束

- `schedule_instance` 是某一天真实生效的班次；`schedule_rule` 只负责生成实例。
- 跨午夜班次以开始时间所在日期为业务日期。
- 休息班不要求上下班时间。
- 临时改班产生变更记录，组织模式可配置是否需要审批。
- 变更不得覆盖历史记录；使用版本号或乐观锁避免并发写入。
- 天气按地点、业务日期和时区匹配；天气失败不能导致排班接口失败。
- 分享快照应在生成时固化，之后原排班变化不应悄悄改变已分享图片。
- 通知任务必须可去重、可重试、可追踪。
- 所有组织资源均需服务端校验成员身份和权限。

## UI 约束

- 以 `06_assets/mockups` 为视觉方向，以 `02_ui` 的令牌和组件规范为实现标准。
- 支持不同屏幕宽度、安全区、文本缩放和较长中文名称。
- 班次颜色不能作为唯一信息载体，必须同时展示文字或图标。
- 所有按钮、表单、加载、空状态、错误状态和权限不足状态都要实现。
- 后台表格在窄屏下应横向滚动或切换卡片形式，不能挤压到不可读。

## 输出要求

不要一次实现整个系统。严格按照 `07_codex_prompts` 的阶段提示词推进。每个阶段都必须达到可构建、可测试、可回滚的状态。
