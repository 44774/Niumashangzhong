# 测试计划

## 1. 单元测试

### 时间与排班引擎

- 普通同日班次；
- 跨午夜；
- 结束时间等于开始时间；
- 无薪休息扣减；
- 时区转换；
- 夏令时边界，即使默认时区无夏令时也要验证可扩展性；
- 循环序列起点、结束日期、长期滚动补齐；
- 临时覆盖后规则不覆盖；
- 重叠和休息间隔冲突。

### 权限

- 普通成员只读自己；
- 部门主管仅管理授权部门；
- 排班员可排班但不可改组织安全设置；
- 审计员只读日志；
- 跨组织 IDOR 测试。

### 通知与天气

- 幂等键去重；
- 改班后取消旧任务；
- Provider 超时降级；
- 过期缓存刷新；
- 勿扰时段；
- 异常天气规则。

## 2. API 集成测试

- 登录与工作空间选择；
- 班次模板 CRUD；
- 单日、循环、批量排班；
- 版本冲突返回 409；
- 临时改班直接生效与审批模式；
- 分享快照不包含隐私字段；
- 审计日志产生；
- 文件导入错误报告；
- 分页与过滤。

使用真实测试数据库，每个测试隔离事务或独立 schema。不要只 mock repository。

## 3. 客户端测试

- 月历渲染不同月份、首日星期、跨月日期；
- 长班次名称和大字体；
- 加载、空、错误、离线；
- 时间选择器跨午夜提示；
- 分享预览隐私开关；
- 深链从消息进入排班详情；
- 多工作空间切换后缓存隔离。

## 4. 端到端场景

1. 新用户创建早班模板并生成一周排班；
2. 查看某天详情与天气；
3. 将当天早班改为晚班；
4. 设置上班前 15 分钟提醒；
5. 生成一周分享海报；
6. 管理员批量安排部门；
7. 员工提交改班，主管审批；
8. 管理员导出班表并查询审计记录。

## 5. 性能测试

- 1000 人组织一个月排班查询；
- 500 人 × 31 天批量预览与提交；
- 同一时间大批通知任务；
- 天气缓存高命中与 Provider 故障；
- 海报和导出任务队列积压。

## 6. 安全测试

- 越权访问；
- 刷新令牌重放；
- 验证码暴力；
- CSV 公式注入；
- 恶意文件上传；
- 分享 token 枚举；
- XSS 与模板注入；
- 日志敏感信息泄露；
- 接口限流与批量滥用。
