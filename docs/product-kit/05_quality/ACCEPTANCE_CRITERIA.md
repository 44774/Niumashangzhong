# 发布验收标准

## 功能

- 用户可以在个人模式完成“创建模板 → 创建排班 → 查看详情 → 临时改班 → 分享”；
- 管理员可以完成“员工/班次 → 批量排班 → 冲突确认 → 审批 → 统计”；
- 月历、周视图和今日详情数据一致；
- 跨午夜班次正确显示并计算；
- 临时改班只影响明确选择的范围；
- 天气失败不影响排班；
- 通知不会因重试重复发送；
- 分享不包含默认禁止字段；
- 审计日志覆盖所有管理员写操作。

## UI

- 三端使用统一品牌和班次颜色；
- 关键页面与效果图结构一致但具备响应式；
- 所有页面有加载、空、错误和无权限状态；
- 大字体与长中文名称不遮挡主要操作；
- 触控目标和键盘焦点符合规范；
- 班次信息不依赖颜色单独表达。

## 工程

- lint、类型检查、测试和构建全部通过；
- OpenAPI 与实现同步；
- 数据库迁移可在空库和已有数据环境运行；
- `.env.example` 完整且无真实密钥；
- 日志脱敏；
- 核心模块具备单元与集成测试；
- 部署文档可让新环境成功启动；
- 失败任务可查询和重试。

## 发布阻断项

以下任一项存在则不得发布：

- 跨组织越权；
- 排班保存后数据丢失或被循环任务覆盖；
- 跨午夜计算错误；
- 分享泄露手机号、内部备注或精确地址；
- 通知重复大量发送；
- 数据库迁移不可回滚或无备份方案；
- 关键流程只有静态页面没有真实接口。
