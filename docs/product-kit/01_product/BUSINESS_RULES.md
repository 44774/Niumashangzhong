# 业务规则

## 1. 班次与时间

- 普通班次必须有开始时间和结束时间。
- 结束时间小于或等于开始时间时，默认视为次日结束；界面应显示“次日”。
- 休息类班次可无时间。
- 工作时长 = 结束时间 - 开始时间 - 无薪休息分钟；结果不能小于零。
- 班次模板被修改后，历史排班实例仍保留创建时的名称、颜色和时间快照。
- 班次颜色仅用于辅助识别，所有界面必须同时展示名称或简称。

## 2. 排班实例

- 每个实例必须具有业务日期、时区、所有者、来源和版本号。
- 来源包括：手动、循环规则、模板复制、导入、管理员批量、临时改班。
- 同一用户同一时间范围内默认不允许两个工作类实例重叠。
- 覆盖冲突必须具有权限，并写入原因和审计日志。
- 已结束实例默认只允许管理员更正；更正不删除旧版本。

## 3. 循环规则

- 规则由起始日期、班次序列、结束策略和时区组成。
- 空序列不可保存。
- 长期规则使用滚动窗口生成未来实例，不无限一次性写入数据库。
- 若某日已有手动或临时修改实例，规则补齐任务不得覆盖该实例。
- 修改规则需要选择作用范围：未来未锁定实例或仅新日期。

## 4. 临时改班与审批

- 个人空间默认直接生效。
- 组织可配置员工是否能直接修改自己的排班。
- 待审批期间，系统保留原排班为当前生效版本，除非组织设置为“申请即暂时生效”。
- 一个排班实例同一时间最多存在一个有效待审批申请。
- 通过和驳回接口必须支持幂等键。
- 审批人不能审批自己无权限管理的成员。

## 5. 通知

- 班次变更后，旧通知任务应取消或失效，新任务重新生成。
- 通知唯一键建议由 `user + schedule_instance + type + trigger_at + version` 构成。
- 处于勿扰时段的非紧急通知延后到允许时间；上班提醒可由用户选择是否忽略勿扰。
- 发送失败按退避策略重试，超过上限进入死信记录。

## 6. 天气

- 天气缓存键包含供应商、坐标网格、日期和时区。
- 用户手动刷新受频率限制。
- 位置来源优先级：实例地点 → 用户默认地点 → 组织默认地点。
- 精确坐标仅在需要天气或导航时使用，分享时默认转为城市或地点名称。
- 天气数据带 `observed_at` 或 `forecast_generated_at`，页面可显示更新时间。

## 7. 分享

- 海报内容必须来自不可变快照。
- 链接分享需要随机高熵 token，数据库只保存 token 哈希。
- 过期或撤销后返回友好页面，不泄露资源是否曾存在。
- 私有备注、审批意见和内部标签默认永不进入分享数据。

## 8. 删除与审计

- 业务数据优先软删除或状态停用。
- 审计日志记录操作者、动作、资源、前后差异摘要、IP/设备、时间和请求 ID。
- 审计日志不可由普通管理员编辑。
- 批量操作记录父审计事件和每项结果摘要。
