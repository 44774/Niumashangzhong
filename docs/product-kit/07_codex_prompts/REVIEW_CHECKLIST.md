# Codex 代码审查清单

## 业务正确性

- 是否把规则和实例混为一谈？
- 临时改班是否误改未来日期？
- 跨午夜和时区是否正确？
- 模板修改是否破坏历史快照？
- 通知是否在变更后正确取消和重建？
- 分享是否固化快照并过滤隐私？

## 权限与安全

- 组织作用域是否由服务端校验？
- 是否存在直接按 ID 查询后返回的越权路径？
- 管理员写操作是否审计？
- 是否把密钥、token、手机号、坐标写入日志？
- 文件和分享链接是否有限时与撤销机制？
- 批量导入和导出是否防注入与滥用？

## 工程质量

- 类型是否共享，而不是三端复制？
- OpenAPI 是否更新？
- 错误码是否稳定？
- 复杂时间逻辑是否有单测？
- 接口是否有集成测试？
- 是否有明显 N+1 查询？
- 批量任务是否幂等？
- 迁移是否向前兼容？

## UI

- 是否使用设计令牌？
- 是否实现加载、空、错误、离线和无权限？
- 是否支持长文本、大字体、安全区和窄屏？
- 班次是否不仅靠颜色区分？
- 按钮是否有明确动作文案？
- 后台表格是否在小屏可用？

## 提交前命令

运行仓库定义的 lint、format check、typecheck、unit、integration、e2e 和 build。记录实际命令及结果，不得只写“应该通过”。
